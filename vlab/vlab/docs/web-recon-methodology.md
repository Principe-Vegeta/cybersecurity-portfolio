# Web Recon Methodology

A repeatable workflow I am practicing in authorized cybersecurity laboratory environments.

## 1. Scope

Identify the exact systems and applications that are authorized for testing.

## 2. Fingerprinting

Inspect HTTP headers and application responses to understand the target environment.

## 3. Passive Mapping

Review standard resources such as robots.txt and sitemap.xml when available within the authorized scope.

## 4. Resource Discovery

Inspect application links and source code to identify routes, files, and references.

## 5. Enumeration

Use appropriate enumeration tools and wordlists to identify accessible resources.

Record HTTP status codes and response differences.

## 6. Validation

Manually inspect interesting findings.

A successful HTTP response does not automatically mean that a vulnerability exists.

## 7. Analysis

Determine what information or functionality is exposed and why it matters.

## 8. Impact

Describe the potential security impact in clear technical terms.

## 9. Remediation

Translate the finding into a practical defensive recommendation.

## 10. Documentation

Record methodology, observations, limitations, and lessons learned.

Sensitive laboratory information, credentials, keys, flags, and private target data should not be published.
